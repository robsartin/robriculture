# ADR-0005: CC-BY 4.0 and open development

- **Status:** Accepted
- **Date:** 2026-08-04
- **Deciders:** Rob

## Context

Per the competition's Winner License terms, a winning submission **and its
source code** must be licensed **CC-BY 4.0**, and winners must provide a
reproducible writeup plus a code repository. Competition data is provided under
Apache 2.0. Any open-source code we depend on must be under an OSI-approved
license that does not restrict commercial use.

## Decision

- License this repository under **CC-BY 4.0** from the first commit (`LICENSE`).
- Develop in the open: clean history, permissively-licensed dependencies only, no
  proprietary or non-redistributable data or models baked into a submission.
- Keep the pipeline reproducible end-to-end (pinned `requirements.txt`,
  deterministic seeds in the harness, a documented build via `build/package.py`),
  so the winner writeup is a byproduct rather than a scramble.

## Consequences

- No licensing surprises at prize time; any submission is already prize-eligible
  on the IP front.
- Constrains dependency choices to compatible OSI licenses and rules out closed
  external data/models in the winning path (external data must be publicly and
  freely accessible to all participants anyway).
- CC-BY requires attribution be preserved by downstream users; acceptable.

## Alternatives considered

- **Decide licensing later.** Rejected: retrofitting license compliance across a
  repo's history and dependency set is error-prone; cheaper to start correct.
- **A permissive code license (MIT/Apache) instead.** The rules specifically name
  CC-BY 4.0 for the winning submission, so we match that to stay eligible.
